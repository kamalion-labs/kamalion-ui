# Design System: Kamalion UI

## 1. Overview

**Creative North Star: "Precision Engineering for Enterprise Workflows"**

Kamalion UI is built for high-performance, complex web applications and enterprise dashboards. The design system prioritizes clarity, structural consistency, and immediate affordances. Every component is designed to feel fast, responsive, and tactile without unnecessary decorative noise.

The system enforces strict accessibility standards (WCAG 2.1 AA) and integrates seamlessly with Tailwind CSS v4, utilizing CSS variables for theme customization across dark and light modes.

**Key Characteristics:**
- **Refined Neutral Surfaces**: Subtle gray-stone/slate tinting across dark and light palettes.
- **Vibrant Violet Accent**: Focused primary action accent color (`#7c3aed` / `violet-600`) with soft state variants.
- **Tactile Feedback**: Subtle active transforms, crisp focus rings (`ring-2 ring-violet-500 ring-offset-2`), and smooth transitions (150-200ms).
- **Compound Architecture**: High-flexibility compound components with Radix UI slot delegation.

## 2. Colors

The Kamalion UI palette is built on a **Restrained** color strategy: clean, tinted neutrals carrying 90% of the visual space, accented by a single violet brand core and high-visibility status indicators.

### Primary
- **Kamalion Violet** (`#7c3aed` / `violet-600`): Used for primary interactive triggers, active tab states, and focus rings.

### Neutral
- **Surface Canvas** (`#ffffff` light / `#0f172a` dark): Main page and panel background.
- **Surface Panel Muted** (`#f8fafc` light / `#1e293b` dark): Secondary container background for sidebars, cards, and input fields.
- **Foreground Text** (`#0f172a` light / `#f8fafc` dark): Primary body copy and headings.
- **Foreground Muted** (`#64748b` light / `#94a3b8` dark): Subtitles, helper text, and inactive labels.

### Feedback
- **Danger Red** (`#ef4444`): Destructive actions, error badges, alert banners.
- **Success Green** (`#22c55e`): Positive confirmations, active status indicators.
- **Warning Amber** (`#f59e0b`): Caution alerts, transient warnings.
- **Info Blue** (`#3b82f6`): Informational callouts and neutral tags.

### Named Rules
**The One Accent Rule.** Primary brand accent color is reserved for active interactive elements and focused triggers. Never use accent fills for static containers or inactive backgrounds.

## 3. Typography

**Display Font:** Inter, system-ui, -apple-system, sans-serif
**Body Font:** Inter, system-ui, -apple-system, sans-serif
**Mono Font:** JetBrains Mono, Fira Code, monospace

**Character:** Clean, highly legible sans-serif hierarchy tailored for dense dashboards and technical application interfaces.

The library declares `--font-sans` / `--font-mono` with a complete fallback stack but ships **no font binaries and makes no network request**. Consumers supply the webfont however they prefer; the stack upgrades automatically once Inter is available. See `apps/kitchensink/src/main.tsx` for the Fontsource wiring.

### Hierarchy

Sizes below map to the semantic utilities generated by `styles/typography.css`, which carry size, line-height, weight and optical tracking together.

- **Display / H1** (`text-display`, bold, 2.25rem, 1.2, −0.021em): Main page headers.
- **Title / H2** (`text-title`, bold, 1.875rem, 1.25, −0.018em): Major section headers.
- **Subtitle / H3** (`text-subtitle`, semibold, 1.5rem, 1.3, −0.015em): Subsection headers and card titles.
- **Section / H4** (`text-section`, semibold, 1.25rem, 1.35, −0.01em): Minor headers.
- **UI Body** (`text-body` / `text-sm`, 0.875rem, 1.5): Labels, table cells, buttons, form text — everything that is application *chrome*.
- **Prose Body** (`Text.Paragraph`, 1rem, 1.75): Long-form reading copy. Deliberately larger than UI body; forcing prose to 14px/1.5 makes running text cramped.
- **Caption / Small** (`text-caption`, 0.75rem, 1.4): Helper text, table headers, timestamps, badges.

Tracking scales **with** size rather than being a flat `tracking-tight`: Inter applies no optical sizing of its own, so display type set at default tracking reads loose.

## 4. Elevation

Kamalion UI uses flat surfaces at rest with subtle 1px borders, elevating surfaces using soft ambient drop shadows only for genuine Z-elevation (modal open, popover float, dropdown trigger).

### Shadow Vocabulary
- **`--shadow-raised`**: A surface at rest on the page — card, table container. Near-shadowless; the border does the separating.
- **`--shadow-raised-hover`**: The lift an interactive card takes on hover.
- **`--shadow-floating`**: Borderless elements resting on the translucent shell — sidebar active pills, switch thumbs, segmented-control knobs.
- **`--shadow-overlay`**: Popovers, dropdowns, tooltips, select menus, the elevated content panel.
- **`--shadow-modal`**: Dialogs, toasts, the app window itself.

### Named Rules
**The Border-First Elevation Rule.** Surfaces are separated by 1px subtle borders (`border-(--color-border)`) at rest. Shadows indicate true physical Z-index elevation above the content surface.

**Dark mode inverts the mechanism.** A drop shadow works by darkening what is behind it; on a dark surface over a dark backdrop there is nothing left to darken and a large blur reads as mud. In dark mode the resting elevation cue is instead a 1px inner highlight along the top edge (light-from-above). This is the one sanctioned place where a raw `box-shadow` value is written, because every Tailwind `--inset-shadow-*` is a dark inset.

## 5. Components

### Buttons
- **Shape:** Full pill (`--button-radius` → `--radius-pill`). Capsule action controls are the theme's identity; see `styles/themes/default/AGENTS.md`. Field controls are deliberately *not* pills — see below.
- **Variants:** Solid, Soft, Outline, Ghost, Danger.
- **Sizes:** `sm` 32px · `md` 40px · `lg` 48px — the same ramp as Input, so a button and a field align on one row.
- **Transitions:** Smooth color and transform feedback (`active:scale-[0.98]`).
- **Focus:** the shared `focus-ring` utility.

### Cards
- **Background:** `bg-(--color-surface-panel)`.
- **Border:** 1px `border-(--color-surface-panel-border)`.
- **Padding:** 20px (p-5) consistent across Header, Body, and Footer.

### Alert Callouts
- **Border:** 1px `--color-{status}-border` (~25%), which is a *different* token from the fill. Painting the border with the fill's own `-soft` token composites the same 10% tint twice over the same surface and lands far too weak to read as a border.
- **Background:** Soft tinted background (`--color-{status}-soft`, 10% opacity status color).
- **Icon:** Status icon optically aligned with title text (`mt-px` against a semibold 16/24 title).
- **Elevation:** Flat. A callout is not elevated above the surface it sits on.

### Inputs & Form Controls
- **Height:** `sm` 32px · `md` 40px (default) · `lg` 48px, matching Button exactly.
- **Shape:** `--radius-control` (8px). Fields are rounded rects, not pills — a capsule text field pushes the caret against the curve and needs ~16px more horizontal padding per field, which fights the density principle. `shape="pill"` is available for search bars, which the theme guide does want as capsules.
- **Focus:** Border tint shift plus the shared `focus-ring` utility.

### Focus

One recipe library-wide, via the `focus-ring` / `focus-ring-within` / `focus-ring-inset` utilities in `styles/utilities.css`.

They use `outline`, **not** `ring`. `ring-offset-<color>` paints the offset gap as an *opaque* fill, which is visibly wrong for anything sitting on this theme's translucent window glass. `outline-offset` renders a genuinely transparent gap and follows `border-radius`, so one recipe works over panel, glass and colored fills with no offset-color token to keep in sync.

### Radii

Strictly descending, so a nested surface always reads tighter than its container:

`--radius-window` 24 → `--radius-panel` 16 → `--radius-card` 12 → `--radius-control` 8 → `--radius-inline` 6. `--radius-pill` is reserved for action controls.

## 6. Do's and Don'ts

### Do:
- **Do** use semantic tokens (`bg-(--color-surface-panel)`, `text-(--color-foreground)`) instead of hardcoded tailwind colors.
- **Do** ensure all interactive components support keyboard navigation and visible focus rings.
- **Do** use `asChild` Radix Slot patterns for custom link/router rendering.
- **Do** use the `focus-ring` utilities rather than hand-rolling a `ring-*` stack per component.
- **Do** neutralise motion to `1ms` under `prefers-reduced-motion`, never `animation: none` — Radix's `Presence` waits on `animationend` to unmount, and `none` suppresses the event, leaving closed dialogs in the DOM.

### Don't:
- **Don't** use colored side-stripe borders (`border-left-4`) as a visual accent on callouts or cards.
- **Don't** apply gradient backgrounds to text or buttons.
- **Don't** use modals for simple inline interactions when progressive disclosure or inline edit can be used.
- **Don't** hardcode pure black `#000000` or pure white `#ffffff` for dark/light neutrals; use tinted stone/slate tones.
